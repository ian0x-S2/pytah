## Prerequisites

Your project needs React <code>{compatibility.requirements.react}</code>,
Tailwind CSS <code>{compatibility.requirements.tailwind}</code>, and
shadcn/ui <code>{compatibility.requirements.shadcn}</code> already
configured. The editor is built on <code>@base-ui/react</code> primitives, not
Radix UI, and is currently validated against Lexical
<code>{compatibility.requirements.lexical}</code>.

## 1. Install with shadcn CLI

There are two supported install styles: a **namespace registry** (recommended,
enables optional feature items) and **direct URLs** (single-item installs).

### Option A: Namespace registry (recommended)

Map the `@pytah` namespace in your project's `components.json`:

```json
{
  "registries": {
    "@pytah": "https://pytah.vercel.app/r/{name}.json"
  }
}
```

Then install with the short name:

```bash
# base editor
bunx --bun shadcn add @pytah/editor

# any optional feature item
bunx --bun shadcn add @pytah/editor-image
```

<Callout title="Required for feature items" variant="warning">
  Feature items (`editor-image`, `editor-tables`, ...) declare
  `registryDependencies: ["@pytah/editor"]`. The CLI can only resolve that
  reference through the namespace mapping above — installing a feature by raw
  URL fails to pull the base editor automatically.
</Callout>

For local development, point the namespace at the dev server instead:
`http://localhost:5173/r/{name}.json`.

### Option B: Direct URL

Single-item installs work without touching `components.json`:

```bash
# local docs/dev server
bun x shadcn@latest add http://localhost:5173/r/editor.json

# published registry
bun x shadcn@latest add https://pytah.vercel.app/r/editor.json
```

The path is always `/r/editor.json`. Only the origin changes between local and
deployed environments.

<Callout title="What gets installed" variant="tip">
  The registry item installs the full editor tree, the required `ui` wrappers,
  `lib/utils.ts`, the Lexical/Base UI dependencies, and the editor highlight
  tokens.
</Callout>

Your app still needs the normal <code>shadcn/ui</code> foundations in place:
React <code>{compatibility.requirements.react}</code>, Tailwind CSS
<code>{compatibility.requirements.tailwind}</code>, a valid
<code>components.json</code>, and the standard <code>@/</code> alias pointing
at <code>src</code>.

<Callout title="Compatibility" variant="tip">
  React <code>{compatibility.requirements.react}</code>, Tailwind CSS
  <code>{compatibility.requirements.tailwind}</code>, shadcn/ui
  <code>{compatibility.requirements.shadcn}</code>, and Lexical
  <code>{compatibility.requirements.lexical}</code> are the versions this
  registry item is currently validated against.
</Callout>

## 2. Manual Copy-Paste Fallback

If you do not want to consume the registry item, install the editor manually.
First install the Lexical editor framework and its companion packages:

```bash
bun add lexical @lexical/react @lexical/rich-text @lexical/list \
  @lexical/code @lexical/link @lexical/table @lexical/html \
  @lexical/markdown @lexical/utils @lexical/selection \
  @lexical/clipboard @lexical/history @lexical/extension
```

Then install the UI dependencies you still need:

```bash
bun add @base-ui/react class-variance-authority clsx \
  tailwind-merge cmdk lucide-react
```

Then copy these directories and files into your project, preserving their
relative paths:

```text
src/
├── components/
│   ├── editor/          ← entire directory (core + plugins + ui)
│   └── ui/              ← ShadCN primitives used by the editor:
│       ├── button.tsx
│       ├── command.tsx
│       ├── dialog.tsx
│       ├── input.tsx
│       ├── input-group.tsx
│       ├── popover.tsx
│       ├── separator.tsx
│       ├── textarea.tsx
│       └── toggle.tsx
└── lib/
    └── utils.ts         ← cn() helper
```

<Callout title="Path alias required" variant="warning">
  The editor imports use the `@/` path alias (mapped to `./src`). A normal
  `shadcn init` setup already gives you this. If your project differs, update
  `tsconfig.json` and your bundler config, or rewrite the imports.
</Callout>

Your global Tailwind v4 stylesheet should import `tw-animate-css`. The registry
item injects the editor highlight tokens automatically.

## 3. Add CSS Tokens

The CLI path adds these automatically. For manual installs, the editor uses two
custom design tokens not in the default ShadCN palette. Add these to your CSS
`:root` and `.dark` blocks:

<CodeBlock language="css">{`:root {
${extractMarkedSource(indexCssSource, "highlight-tokens-light")}
}

.dark {
${extractMarkedSource(indexCssSource, "highlight-tokens-dark")}
}`}</CodeBlock>

Then register them in your Tailwind v4 `@theme inline` block:

<CodeBlock language="css">{`@theme inline {
${extractMarkedSource(indexCssSource, "highlight-theme-bridge")}
}`}</CodeBlock>

### Composition First

The default `Editor` is intentionally ready-made, but it now also exposes
lego-like extension points so consumers can disable chrome, replace surfaces,
add plugins, and register custom Lexical nodes without editing the internal
editor files.

```tsx
import { Editor } from "@/components/editor/editor";
import { imageFeature } from "@/components/editor/plugins/image/feature";
import { youtubeFeature } from "@/components/editor/plugins/youtube/feature";
import { MyAnalyticsPlugin } from "@/components/editor/plugins/my-analytics/plugin";
import { MyCalloutNode } from "@/components/editor/core/nodes/my-callout/node";

export function CustomEditorExample() {
  return (
    <Editor
      chrome={{ header: false, outputs: false }}
      extraNodes={[MyCalloutNode]}
      extraFeatures={[imageFeature, youtubeFeature]}
      features={{
        floatingToolbar: false,
        slashCommand: true,
      }}
      pluginSlots={{
        afterEditable: <MyAnalyticsPlugin />,
      }}
      slots={{
        actionBar: ({ onReset }) => (
          <button onClick={onReset} type="button">
            Reset document
          </button>
        ),
      }}
      toolbar="full"
    />
  );
}
```

### Editor Props

The `Editor` component accepts the following props:

<InterfaceSource name="EditorProps" source={editorTypesSource} />

The most important composition hooks are:

```tsx
features        // enable/disable built-in behavior plugins (core only)
extraFeatures   // install content features (images, tables...) and custom capabilities
chrome          // show/hide default shell/header/footer/action bar/output panels
slots           // replace default visual surfaces
pluginSlots     // mount extra plugins around the built-in plugin stack
extraNodes      // register additional Lexical nodes
namespace       // customize the Lexical namespace when embedding multiple editors
```

Installed feature items are composed through their feature descriptors — see
`/docs/composition` for `extraFeatures`. For a deeper breakdown of those
contracts, continue with the `Composition` and `API` pages.

<Callout title="That's it" variant="tip">
  The editor is self-contained. It manages its own Lexical composer, plugins,
  and toolbar by default, while still exposing public extension points when you
  need a more custom composition. No providers or context wrappers are needed
  beyond what React and your CSS already provide.
</Callout>
