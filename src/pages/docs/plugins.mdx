Every editor feature is implemented as a Lexical plugin — a React component
rendered inside the `LexicalComposer` context. Plugins are either **visual**
(render UI like toolbars and menus) or **headless** (register commands and
transforms, return `null`).

## Adding a Custom Plugin

Every plugin follows the same pattern: a React component that accesses the
editor through `useLexicalComposerContext()`, registers its behavior in a
`useEffect`, and either returns `null` (headless) or renders UI (visual). The
steps below walk you through adding a new headless plugin from scratch.

### Step 1 — Create the plugin file

Create `src/components/editor/plugins/my-feature/plugin.tsx`. Define a Lexical
command and register a handler for it inside `useEffect`. The return value of
`registerCommand` is an unsubscribe function — returning it from `useEffect`
cleans up automatically when the component unmounts.

```tsx
// src/components/editor/plugins/my-feature/plugin.tsx
import { useLexicalComposerContext } from "@lexical/react/LexicalComposerContext";
import { COMMAND_PRIORITY_EDITOR, createCommand } from "lexical";
import { useEffect } from "react";

export const MY_COMMAND = createCommand<void>("MY_COMMAND");

export function MyPlugin() {
  const [editor] = useLexicalComposerContext();

  useEffect(() => {
    return editor.registerCommand(
      MY_COMMAND,
      () => {
        editor.update(() => {
          // mutate the Lexical state here
        });
        return true; // true = command was handled, stop propagation
      },
      COMMAND_PRIORITY_EDITOR
    );
  }, [editor]);

  return null;
}
```

<Callout variant="tip">
  If your plugin renders UI (a toolbar button, a popover, etc.), return JSX
  instead of `null` and import the ShadCN primitives from `@/components/ui/`.
  Dispatch commands to the editor with `editor.dispatchCommand(MY_COMMAND,
  payload)`.
</Callout>

### Step 2 — Mount the plugin via Editor props

For most custom behavior, you do not need to edit
`src/components/editor/ui/content.tsx`. Mount your plugin through
`pluginSlots` so it composes with the default editor stack.

```tsx
import { Editor } from "@/components/editor/editor";
import { MyPlugin } from "@/components/editor/plugins/my-feature/plugin";

export function MyEditor() {
  return (
    <Editor
      pluginSlots={{
        afterEditable: <MyPlugin />,
      }}
    />
  );
}
```

Use `beforeDefault` and `afterDefault` for plugins that should also run in
read-only mode. Use `beforeEditable` and `afterEditable` for edit-only
behavior.

### Step 3 — Add a custom node (optional)

If your feature needs a custom Lexical node (e.g., a decorator for rendering
React UI inside the editor), create it under
`src/components/editor/core/nodes/my-feature/node.tsx`. Export the class plus
the standard `$create` and `$is` helpers that Lexical convention expects.

```tsx
// src/components/editor/core/nodes/my-feature/node.tsx
import {
  $applyNodeReplacement,
  DecoratorNode,
  type LexicalNode,
} from "lexical";

export class MyFeatureNode extends DecoratorNode<JSX.Element> {
  static getType(): string {
    return "my-feature";
  }

  static clone(node: MyFeatureNode): MyFeatureNode {
    return new MyFeatureNode(node.__key);
  }

  createDOM(): HTMLElement {
    return document.createElement("div");
  }

  updateDOM(): false {
    return false;
  }

  decorate(): JSX.Element {
    return <div>Your rendered UI here</div>;
  }
}

export function $createMyFeatureNode(): MyFeatureNode {
  return $applyNodeReplacement(new MyFeatureNode());
}

export function $isMyFeatureNode(
  node: LexicalNode | null | undefined
): node is MyFeatureNode {
  return node instanceof MyFeatureNode;
}
```

### Step 4 — Register the node via Editor props (optional)

Custom nodes must be declared in the editor config before Lexical can
serialize or deserialize them. For most consumers, use the public
`extraNodes` prop instead of editing `src/components/editor/core/config.ts`.
If the node belongs to a whole capability (with a plugin, transformers, and
slash command), prefer the `extraFeatures` prop so all of it is wired by one
descriptor.

```ts
import { Editor } from "@/components/editor/editor";
import { MyFeatureNode } from "@/components/editor/core/nodes/my-feature/node";

export function MyEditor() {
  return <Editor extraNodes={[MyFeatureNode]} />;
}
```

<Callout variant="tip">
  Keep `types.ts`, `commands.ts`, and `utils.ts` co-located inside
  `plugins/my-feature/` so the feature is self-contained and easy to remove.
</Callout>

## Extending the Slash Command Menu

For consumers, the supported way to add a slash command (together with its
nodes, plugin, and markdown transformers) is the `extraFeatures` prop on
`Editor`. Declare an `ExtraEditorFeature` once and the composition surface
wires everything for you — no edits inside the slash-command folder.

### Consumer path — `extraFeatures`

A feature descriptor bundles the ID, optional behavior plugin, Lexical nodes,
markdown transformers, and the slash-command ids it contributes. The menu
picks up any id you add.

```tsx
import { Editor } from "@/components/editor/editor";
import { MyCalloutNode } from "./my-callout-node";
import { MyCalloutPlugin } from "./my-callout-plugin";

export function MyEditor() {
  return (
    <Editor
      extraFeatures={[
        {
          id: "callout",
          plugin: MyCalloutPlugin,
          nodes: [MyCalloutNode],
          transformers: [CALL_OUT_TRANSFORMER],
          slashCommandIds: ["callout"],
        },
      ]}
    />
  );
}
```

### Built-in authoring path — the three-file contract

When contributing a *built-in* command (shipped in the default editor), add
its id to `EDITOR_FEATURES` in `core/features.tsx` instead of reaching into
the slash-command internals. The command menu is driven by the feature
registry: the plugin, nodes, and transformers for the same capability live in
its own feature folder.

The slash-command folder still holds three files that describe each command.
Editing them is only required when the command itself needs bespoke behavior
that the feature descriptor can't express.

| File | What you add |
| --- | --- |
| `types.ts` | A new literal to the SlashCommandId union |
| `commands.ts` | A SlashCommand object (label, description, icon, keywords) |
| `executors.ts` | A Lexical mutation function keyed by your new ID |

### Step 1 — Register the command ID

Open `plugins/slash-command/types.ts` and add your new identifier to the
`SlashCommandId` union. TypeScript will then enforce that the other two files
are updated to match.

```ts
// src/components/editor/plugins/slash-command/types.ts
export type SlashCommandId =
  | "paragraph"
  | "h1"
  | "h2"
  | "h3"
  | "quote"
  | "code"
  | "bullet"
  | "number"
  | "check"
  | "image"
  | "youtube"
  | "collapsible"
  | "columns"
  | "table"
  | "hr"
  | "callout"; // ← add your ID here
```

### Step 2 — Add the command definition

Open `plugins/slash-command/commands.ts` and push a new entry into the
`SLASH_COMMANDS` array. Pick a `lucide-react` icon, write a short
`description`, and add `keywords` so the fuzzy filter can find your command
even when the user doesn't type the exact label.

```ts
// src/components/editor/plugins/slash-command/commands.ts
import { AlertCircleIcon } from "lucide-react"; // ← add icon import

export const SLASH_COMMANDS: SlashCommand[] = [
  // ...existing commands
  {
    description: "Highlighted callout block",
    icon: AlertCircleIcon,
    id: "callout",
    keywords: ["callout", "note", "info", "alert", "warning"],
    label: "Callout",
  },
];
```

### Step 3 — Add the executor

Open `plugins/slash-command/executors.ts` and add an entry to the
`SLASH_COMMAND_EXECUTORS` map. The function receives the top-level
`ElementNode` where the slash text lives and should replace or transform it
into your target block.

```ts
// src/components/editor/plugins/slash-command/executors.ts
import { $createParagraphNode } from "lexical"; // already imported

export const SLASH_COMMAND_EXECUTORS: Record<
  SlashCommandId,
  (element: ElementNode) => void
> = {
  // ...existing entries
  callout: (element) => {
    const paragraph = $createParagraphNode();
    element.replace(paragraph);
    paragraph.selectEnd();
  },
};
```

<Callout title="Commands that need user input" variant="info">
  If your command requires extra data before inserting (a URL, a file, a
  preset choice), intercept it in `plugin.tsx` before the executor runs:
  capture the `targetNodeKey` from the current selection, store it in state,
  and open a dialog. The existing `image`, `youtube`, and `columns` commands
  follow this pattern and are good reference implementations.
</Callout>
