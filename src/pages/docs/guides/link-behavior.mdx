## utils.ts

Three URL helpers used by the floating editor and `LinkPlugin`'s `validateUrl` prop.

| Export | Purpose |
| --- | --- |
| `LINK_PLACEHOLDER_URL` | Sentinel value (`"https://"`) used as the default when creating a new link so the input is pre-filled. |
| `normalizeEditorLinkUrl(value)` | Trims whitespace, adds `mailto:` for bare email addresses, adds `https://` for `www.` prefixed strings. |
| `isValidEditorLinkUrl(value)` | Returns `true` for any URL whose protocol is one of `http:`, `https:`, `mailto:`, `sms:`, `tel:` — or the placeholder. |
| `sanitizeEditorLinkUrl(value)` | Returns `about:blank` for disallowed protocols, otherwise returns the normalised URL. |

## floating-link-editor.tsx

The link surfaces follow the Google-Docs interaction model, and a click that merely places the caret inside a link never opens anything:

1. **Hover chip (`preview`)** — hovering a link shows a compact preview (`FloatingLinkPreviewChip`) anchored to the hovered link's rect (6px below). It renders through the shadcn `HoverCard` (Base UI preview card) in controlled mode — open state is plugin-driven because the link lives inside Lexical-owned DOM — and gains Base UI's native dismissal (Escape, outside press, pointer-leave bridging) on top of the plugin tracking. It is pointer-driven and caret-independent: detection runs on document-level `pointerover`, and leaving every link arms a 120ms grace-period dismissal so the pointer can travel from the text into the chip. Hovering the chip or the edit card keeps the current surface alive.
2. **Edit card (`edit`)** — the chip's **Edit** button, the floating toolbar's link button or Cmd/Ctrl+K open the full card (shadcn `Popover` over the surface rect): a **link-text field**, a **URL field** (`Add a link` placeholder) and **open-in-tab / remove / close** actions. Edit mode only controls initial focus (the URL input). `Enter` applies the URL and display text, moves the caret just after the link and closes the card; `Escape`/outside press close it. Clicking Edit also selects the link's text so the selection sync can carry the card.

Both surfaces render through `FloatingLinkEditorSurfaces` from the same virtual anchor produced by the state machine in `floating-link-editor-reducer.ts` (`closed` / `preview` / `edit`). A closed surface stays closed — a bare selection sync never re-opens anything (the old Escape/click reopen loop is structurally impossible).

### Commands handled

| Command | Priority | Behaviour |
| --- | --- | --- |
| `SELECTION_CHANGE_COMMAND` | LOW | Syncs link state and surface anchoring on every selection change. |
| `OPEN_FLOATING_LINK_EDITOR_COMMAND` | HIGH | Opens the edit card (dispatched by the floating toolbar's link button and the chip's Edit). |
| `KEY_DOWN_COMMAND` | HIGH | Cmd/Ctrl+K toggles the link: removes it if the selection is already a link, otherwise creates a new one and opens the card. |
| `KEY_ESCAPE_COMMAND` | HIGH | Closes the card/chip when the selection lives in a link. |
| `CLICK_COMMAND` | LOW | Cmd/Ctrl+click opens the link URL in a new tab while editing. |

## Registration

No custom nodes are required. `LinkBehaviorPlugin` is part of the always-mounted default stack, and the floating link editor ships behind the `floatingLinkEditor` feature flag. To add the floating editor to a custom composition, contribute a descriptor via `extraFeatures`:

```tsx
<Editor
  extraFeatures={[
    {
      id: "floatingLinkEditor",
      plugin: FloatingLinkEditorPlugin,
    },
  ]}
/>
```

<Callout title="Keyboard shortcut" variant="tip">
  Cmd/Ctrl+K is handled entirely inside `FloatingLinkEditorPlugin`. Pressing it
  on plain text creates a link and opens the editor; pressing it again on an
  existing link removes it. No toolbar wiring is needed for the shortcut to
  work.
</Callout>
