# Changelog

## Unreleased

### Fixed

- Switching the code-block theme family (or any highlight-transform re-registration) re-tokenized the parent block once per dirty child instead of once per pass. Registering a `TextNode` transform dirty-marks every text node — and every token IS a text node (`CodeHighlightNode`) — so the plugin's own sync hooks ran `$tokenize` on the block once per token child: a 40-line TypeScript block measured ~1,700 tokenize calls and ~700ms of synchronous work inside the update that closes the theme select, which is why the picker sat open and the block recolored about a second late on bigger snippets (a one-line block hid it at a dozen calls). The pre-transform in `plugin.tsx` now keeps the same re-entrancy guard upstream's `codeNodeTransform` already has (`nodesCurrentlyHighlighting`): the first child syncs the block, the rest skip until the update listener clears the window at commit end, and each registration starts a fresh window so an aborted update can't wedge a key. A family switch now costs one tokenize plus one splice per block (~5ms measured); mode-only flips stay at zero. Covered by a new plugin test (a family switch on a 40-line block tokenizes at most once per pass, not once per token child).

- Toggling light/dark flashed the old syntax palette on code blocks: the shell (`.dark` flips synchronously via a layout effect) and the block background (`--editor-code-bg`) repaint in the same frame, but token colors were baked as inline hex into every `CodeHighlightNode` at tokenize time and only changed through a transform-driven Lexical re-tokenize that landed one or more painted frames later. Tokens now carry theme-agnostic `color: var(--editor-code-token-*)` references, and `EditorContent` provides the palette hexes as `--editor-code-token-*` vars on the same wrapper as the background — so a mode flip recolors every block purely through CSS, with no Lexical work. Mode-only flips also skip the re-tokenize entirely (the role resolver is family-gated, never light/dark), and the transform registration moved to a layout effect so family switches that remap roles commit their splice before paint. The dead Prism `codeHighlight` Tailwind map in `core/theme.ts` went away with it (every typed token already masked those classes with inline styles); the code block's base-text color moved to `.editor-code-block` in `core/tokens.css`. Code copied as HTML now carries `var()` color references that resolve inside the app and degrade to plain text color elsewhere (previously the exported hex was baked per node). Covered by new plugin tests (mode-only flips preserve child keys and run zero tokenize passes; family switches still tokenize and remap roles) and a registry test for the token var coverage. Registry snapshots rebuilt.

### Fixed

- The slash menu kept its highlight on the previously chosen item when it reopened: the raw selection survived the menu closing (execute, escape, selection lost), so a fresh `/` query started with focus and accent on the last used block type. Opening the menu now resets the highlight to the first item; typing while the menu stays open still keeps the current highlight.
- Clicking an image after a select-all (or any range selection spanning it) showed no resize handles. Lexical 0.42's `node.isSelected()` is true whenever a selection _contains_ the node, so the selection hook was already `true` from the range selection; clicking the image then created a `NodeSelection` without changing that state, React bailed out of re-rendering and the resize overlay never mounted. The image component now tracks NodeSelection membership in state and re-renders on every transition, so handles appear whenever the image itself is selected — and no longer on images merely covered by a text selection.
- Pressing Ctrl/Cmd+A with the selection inside a code block now selects only that block's content instead of escaping to the whole document. Lexical's default select-all always expanded to the entire editor, so a select-all fired while editing code lost the block context. A scoped `SELECT_ALL_COMMAND` handler in the code-block feature resolves any selection endpoint that reaches a `CodeNode` and spans exactly its selectable leaves (text and tabs, across line breaks); selections outside code blocks still fall through to the document-wide select-all.
- The Excalidraw drawing surface now returns the caret to the editor when it closes (save, discard or X). The dialog is portaled outside the contenteditable, so on unmount the browser dropped focus on `body` instead of falling back to the editor — typing a fresh slash query right after closing did nothing, and no second drawing could be inserted until the user clicked back in.
- Pasting inside the Excalidraw editing surface landed in the document instead of the drawing board: the full-screen editor dialog rendered inside the contenteditable, so every canvas `paste`/`keydown` bubbled into Lexical's root listeners before excalidraw saw it. The dialog now portals to `document.body`, keeping the editing surface's clipboard and keyboard events out of the editor.
- Pasting a drawing copied from an Excalidraw canvas (`{"type":"excalidraw/clipboard",…}` in the clipboard's `text/plain`) dumped the raw JSON into the document as a long plain-text paragraph. The Excalidraw plugin now intercepts such pastes and inserts a proper drawing block with the copied scene (regular text/JSON pastes fall through untouched).

### Fixed

- Clicking a checklist item after closing the floating link edit card snapped the caret back into the link text. Closing the card is focus-destructive: its inputs own the native selection while open, so unmounting them (X, Escape, outside press, Apply) kills it — but the Lexical selection kept pointing at the link (`linkNode.select()` runs on open). The checklist handler preventDefaults `pointerdown` (so the native selection can't move to the item), focuses the `<li>` and re-syncs the DOM selection with the editor's selection — which force-restored the stale link selection and yanked focus back. An edit→closed transition now reconciles the selection: if the native selection survived inside the editor root it stays untouched, otherwise the stale Lexical selection is dropped so no later update (checklist tick, style change) resummons the vanished caret.
- The `h6` heading rendered at 16px, 1px below the 17px body text, breaking the `h1 > h2 > … > body` hierarchy (every other level sits above body). `--editor-h6-size` is now `1.0625rem` (17px, equal to body, semibold weight keeping it distinct). Registry snapshots rebuilt.
- The editor footer's stats group used `gap-3` while the header, action bar and every other chrome row use `gap-2`: the related stats sat farther apart (12px) than the groups they belong to (8px). The stats row now uses `gap-2`, matching the dominant chrome pattern.
- Small spatial-hierarchy fixes from a compact/comfortable geometry review (`@ui-geometry`, contract documented under "Density presets" in `/docs/theming`): the block-type menu's label/description stacked with no gap (now `gap-0.5`); the math popover's four sections shared one uniform gap (flow is now `gap-2` with the action row separated by `pt-2`); the layout preset card's internal gap equaled the grid gap between cards (now `gap-2` inside vs `gap-3` between). Chrome control sizes stay tool-density (24/28px) in both modes by design.
- Toggling `density` left the code-block line numbers and the theme/language pickers stranded at their old positions (numbers and selects rendered over unrelated content below the block). Both overlays measured their anchors with `getBoundingClientRect` but only re-collected on Lexical edits (plus window resize for the chrome) — and the density switch changes only CSS vars, producing no edit and no resize. Both plugins now re-collect on a `ResizeObserver` over the gutter host, which tracks the density-carrying wrapper through density, zen-mode and container changes.
- Clicking an item in the TOC popover closed it immediately: the click handler moves focus to the editor (`editor.getRootElement()?.focus()`), which fired the sidebar's `onBlurCapture` and flipped the popover back to the mini-bars while the pointer was still inside. Hover and keyboard focus are now independent open sources — the popover only closes when the pointer leaves (150ms grace) **or** focus moves outside, so a click keeps it open under the pointer, and keyboard users keep focus-open/focus-out semantics.

- The editor interface passes an accessibility/polish review (better-accessibility, better-writing, better-typography, better-colors, better-ui): the static block-type toolbar now carries `role="toolbar"` with a label like the floating toolbar; the Markdown/HTML output textareas got accessible names; the TOC rail got visible focus rings and opens its heading popover on keyboard focus (closing on blur) instead of being hover-only; selected color swatches announce their state with `aria-pressed` plus an in-swatch check instead of a color-only ring (the Clear button got a focus ring); the math editor popover now renders as a proper `editor-floating` surface with focus rings on Inline/Block/remove/cancel/save, `aria-pressed` on the Inline/Block toggles, sentence-case "Edit TeX equation" and a `transition-colors` instead of `transition-all`; the toolbar Insert popover uses the `editor-floating` token surface, labels its listbox and colors the active option's text (`text-accent-foreground`); the link chip/edit-card "open in new tab" buttons are real anchors (`<a target="_blank">`) so middle-click and Cmd/Ctrl-click work; "Delete table" in the table menu shows destructive hover feedback; the layout preset dialog title/description copy was simplified ("Choose column layout" / "Select a column layout preset."); the YouTube dialog's hint text is wired to the input via `aria-describedby` and dropped its raw backticks.

- Dropping a draggable block now immediately positions the floating drag handle at the dropped block's new position and synchronizes upstream Lexical's internal draggable block element state. Previously, the handle remained orphaned at its pre-drag coordinates until the user moved the pointer across the editor.

- The `EditorWithToc` TOC rail no longer floats at a hardcoded `top-24` viewport offset while the editor body starts lower on the page. The rail's fixed `top` is now measured from the editor content column's top (re-measured on resize and when the TOC toggles, which also covers zen-mode layouts), so it starts at the same vertical level as the editor regardless of what the consumer renders above it.

- The floating link editor got stuck after its first edit-card interaction: a hover dismissal (`unhover-link`) that arrived while the edit card was open — the stray `pointerleave` the browser fires when the chip unmounts under the pointer after clicking **Edit**, or the 120ms grace timer expiring while the pointer rested on plain content outside the card — cleared the card's anchor, so the card unmounted while `isLinkEditMode` stayed on and `hover-link` was then swallowed by edit mode forever: every link in the document stopped opening its hover chip. In edit mode the card is not hover-driven; `unhover-link` now only drops the hover target and leaves the card's anchor (and the card itself) untouched, keeping the hover interaction repeatable indefinitely. Verified in a real browser (CDP) across hover → chip → Edit → card → Escape/outside-press → re-hover cycles, rapid link↔chip oscillation, and independent re-targeting between two links.
- The math formula trigger is now a native `<button>` instead of a `<span role="button">`, so screen readers and keyboards get built-in button semantics (Enter/Space activation, focus handling) instead of re-implemented ones. Visuals are unchanged (Tailwind preflight already resets button chrome; trigger keeps its KaTeX rendering and selected/hover states).
- The Excalidraw full-screen editor and its discard-confirm overlay now render as native `<dialog>` elements instead of `<div role="dialog">` / `<div role="alertdialog">`, so assistive tech gets built-in dialog semantics. Both stay non-modal (`open`, no `showModal`) with UA chrome reset, preserving the existing focus and custom Escape behavior (the canvas keeps its own Escape semantics).

### Changed

- The link hover preview chip renders on the popover background with a real `border-border` outline: the 1px `box-shadow` ring (`--editor-floating-ring`) stays dropped via the `editor-floating-no-ring` token class — background and drop shadow unchanged, only the edge treatment swapped from shadow-ring to border.
- The floating link edit card locks the page scroll while it is open: the popover is mounted as a Base UI modal (`modal` on the `Popover` root), so wheel scrolling can no longer move the page out from under the card's anchor while the link text/URL is being edited. Scrolling is restored as soon as the card closes (Escape, outside press or the close button). The hover preview chip stays non-modal — it must never hijack scroll on hover.
- The link hover preview chip renders through a shadcn `HoverCard` (Base UI preview card, new `components/ui/hover-card.tsx` primitive) instead of a `Popover`: hover previews get Base UI's purpose-built dismissal for free — Escape and outside press close the chip, and pointer movement between the link and the chip is bridged natively. Open state stays controlled by the plugin because the link element lives inside Lexical-owned DOM. The edit card keeps its `Popover`.
- The floating link interaction follows the Google-Docs flow now: hovering a link shows a compact **preview chip** (open-in-tab, link label, **Edit**) anchored under the hovered link — pointer-driven and caret-independent (document-level `pointerover`, 120ms grace period so the pointer can travel into the chip). Clicking a link merely places the caret and never opens anything. The chip's **Edit** button selects the link text and opens the full Notion-style card (link-text field, URL field, open-in-tab / remove / close); the floating toolbar's link button and Cmd/Ctrl+K still open the card directly. The three surfaces (`closed` / `preview` / `edit`) are one state machine — a closed surface stays closed until hover or an explicit action, which structurally removes the old "card re-opens after Escape/outside press" loops.
- The floating selection toolbar now hides itself when the Link button opens the link card, and returns on the next selection change — the card is the active editing surface while the selection lives inside the link.
- The static toolbar's "Turn into" dropdown is a little narrower (`w-64` → `w-56`, 256px → 224px).
- The home page "Choose your path" list no longer appends a `→` separator after each step description.
- Editor radii are capped at `rounded-md`. Every `--editor-*-radius` token that resolved to `lg` or larger (shell, floating, table, image + image frame, code, collapsible, layout, layout item/option, youtube) now resolves through `var(--radius-md, 0.5rem)`, and the editor's plugin surfaces plus the shared primitives it renders (button, input, select, popover, dialog, dropdown menu, command, sidebar, textarea, toggle, excalidraw, TOC, slash menu) drop `rounded-lg`/`xl`/`2xl` for `rounded-md`. Corners now follow the consumer theme (override `--radius`) and nothing in the editor renders larger than the cap.

### Fixed

- Editing the link title in the floating link card silently did nothing — the editor kept the old label. `submitToolbarLinkText` replaced the link's children with `linkNode.clear()` + `append()`, and `clear()` removes the text node the caret is currently anchored to first; Lexical's lost-selection repair then fails the "selection has been lost" dev check, which is reported through `editor._onError` and rolls the whole update back with no visible error (and the returned promise still resolves). The children are now replaced with a single `splice` — inserting the replacement text before removing the old children keeps the selection anchored to a live node — and the replacement text inherits the format/style of the first text child, so a bold link stays bold after a title edit. Covered by a new `submitToolbarLinkText` regression suite (`floating-toolbar/actions.test.tsx`, both the chip's whole-link-selection flow and the toolbar's text-selection flow).
- The link hover chip's **Edit** button wrapped its pencil icon and "Edit" label onto two lines (it used the fixed-width `icon-xs` button size with text inside), and the open-in-tab button sat at a different height (20px vs 24px), visibly misaligning the chip row. Both buttons now render at the same 24px height (`icon-xs` + the text-sized `xs` variant) and the link label flexes so it truncates instead of pushing the actions around.
- The floating link edit card was locked to the popover's fixed `w-72` (288px) with no viewport cap, overflowing narrow viewports. Both floating link surfaces (hover chip card and edit card) now cap their width at `calc(100vw - 2rem)`, and the edit panel fills its container instead of carrying a redundant `min-w-72`.
- The link hover chip often failed to survive the first mouse pass: the 120ms grace-period timer armed whenever the pointer crossed non-link content was **never cancelled on link entry**, so it fired while the pointer was still resting on the link and dismissed the freshly opened chip (~100–130ms after it appeared). Slow pointer paths could dodge it by luck (the timer expired before the link was reached), which is why the second pass usually worked. The grace period is now owned by a `HoverBridge` (`floating-link-hover-bridge.ts`, unit-tested via an injectable scheduler): entering a link or a chip/card surface always cancels a pending dismissal — the grace period is a pointer-travel bridge, not an idle timeout. Verified in a real browser (CDP): fast flick and bottom-up approaches that failed consistently now open the chip on the first pass (12/12 trajectories).
- Clicking a link placed the caret inside it and rendered the edit card, but the same click's `pointerup` closed it right away: the popover mounts mid-gesture (it appears on the frame after `pointerdown`), and Base UI completed the very gesture that placed the caret as an outside press. This class of self-dismissal is fixed twice over: the card is only mounted by explicit actions now (chip Edit / toolbar / Cmd+K), and hover chips + the card ignore mid-gesture `outside-press` requests while the selection sync owns open/close of the selection-driven surfaces.
- The floating link editor now opens when the toolbar Link button or Cmd/Ctrl+K creates a link. The plugin's unmount cleanup cancelled the scheduled `requestAnimationFrame` without clearing its ref; under React StrictMode (dev) the double-mount then left the ref pointing at a dead frame forever, so `scheduleLinkEditorUpdate` early-returned on every call, the selection sync never ran, and the card never rendered. The schedule/cancel is now one symmetric effect that clears the ref on cleanup.
- The vertical `<Separator>` primitive no longer ships `data-vertical:self-stretch`. With a definite height (every toolbar separator sets `h-4`/`h-5`), `stretch` makes flexbox fall back to `flex-start`, so separators sat at the top of the row instead of centering — they now center via the parent's `items-center` on every toolbar (floating, static and block-type).
- The slash menu's keyboard navigation no longer freezes while filtering: arrow keys walked the full command list, so every press re-synced the highlight to the first visible item, and the handlers stayed registered (swallowing arrows/enter) when the query matched nothing. `move-selected-command` now walks the filtered list, key handling and scroll-into-view are gated on the menu actually being visible, and the first arrow press off a stale (filtered-out) selection lands on the adjacent item instead of re-syncing to the first.

### Added

- The floating selection toolbar gained a "⋮" overflow menu at the end of the row, grouping super/subscript (with an active-state check), text alignment (left/center/right/justify) and indent/outdent into a dropdown so the toolbar itself stays a single row. The row is now ordered like the reference: "Turn into" block dropdown (reusing the static toolbar's `BlockTypeDrop`, feature-gated through the resolved slash command ids so options follow the enabled feature set), inline format toggles, colors, link, overflow menu. The toolbar stays alive while any of its popovers (color pickers, Turn Into menu, overflow menu) is open.
- `BlockTypeDrop` accepts a `variant` prop: `"full"` (default, unchanged static-toolbar layout with descriptions and the Insert section) or `"compact"` — used by the floating toolbar — which renders only the conversion options (Text, Heading 1–3, Bulleted list, Numbered list, To-do list, Blockquote, Code block) as single-line items, gives the trigger a `min-w-32` floor width with the label left-aligned (chevron pushed to the right edge), and sizes the menu to its trigger's width.
- The floating toolbar's vertical separators are vertically centered again: the Base UI `Separator` primitive ships `data-vertical:self-stretch`, which combined with a fixed `h-5` pushed the separators to the top of the row instead of centering them.

## 0.1.2

### Fixed

- The floating selection toolbar no longer overflows the browser viewport. The toolbar is anchored at the selection midpoint with `translate(-50%, -100%)`; the rendered box is now measured and clamped against the viewport edges (8px margin) in a pre-paint layout pass, so selections at the start/end of a line or at the very top of the viewport keep the toolbar fully on screen.
- The TOC rail and popover are compact, height-capped outlines again. The collapsed mini-bars rail caps at `max-h-[45vh]` (previously it grew with the heading count) and the hover popover caps at `55vh` (previously `70vh`), both scrolling via wheel/touch with the scrollbar hidden through a new `scrollbar-hidden` utility shipped in `editor.css` — the old `scrollbar-thin` classes required `tailwind-scrollbar`, which the registry never declared, so they were dead code. Spacing, dash widths, popover nesting steps and the active-dash treatment (now a flat color swap, no scale/shadow pop) are densified throughout.

## 0.1.1

### Fixed

- **Open latency eliminated for seeded editors** (upstream of a consumer report measuring first content paint at ~3.1s):
  - `initialMarkdown`/`initialHtml` are now converted inside the composer's first editor state (`initialConfig.editorState`) instead of a post-mount effect. The first paint already contains the document — no empty-editor flash and no second full-document update. The post-mount seeding path remains for standalone `EditorStatePlugin` usage (new opt-in `seededViaConfig` prop); `emitInitialSnapshot` parity is preserved by emitting the initial snapshot once from the already-populated state.
  - `CodeHighlightPlugin` arms Shiki highlighting one frame after mount (double `requestAnimationFrame`). Code-heavy documents now paint as plain code text immediately; tokenization and per-node re-splicing land off the click-to-content critical path. One frame passes before Tab-capture inside code blocks is active.
  - The editable region opts out of native spellchecking (`spellCheck={false}` on `ContentEditable`). WebKitGTK boots its enchant broker on the first spellcheck-enabled region and, with no enchant backend installed, probes every provider serially on the web-process main thread — a ~2s first-mount freeze invisible to JS profilers. Consumers that want red squiggles can re-enable spellchecking per instance.

## 0.1.0

### Added

- **Selective snapshot serialization** via the new `features.snapshot` flag bag on `Editor`:
  - `snapshot.html` / `snapshot.markdown` / `snapshot.text` (all default `true`) — a disabled output is skipped entirely (never computed) and surfaces as `""` on the `EditorSnapshot`. Markdown-only consumers no longer pay for per-keystroke HTML serialization.
  - `snapshot.emitInitialSnapshot` (default `true`) — the programmatic seed update that loads `initialMarkdown`/`initialHtml` is tagged with Lexical's `$addUpdateTag("pytah-seed")`; when this option is `false`, the tagged update no longer triggers `onChange`/`onSnapshotReady`, so the first emission happens on the first real edit.
  - With `snapshot.text: false`, the per-change text serialization and its state update are skipped as well.
- The outputs panel copy handlers serialize on demand when their output is disabled, so copy-as-HTML/Markdown still works with the panel rendered.
- `readEditorSnapshot(editor, transformers, options?)` accepts an options bag to skip disabled outputs (`EditorSnapshotOutputs`).

### Changed

- `initialMarkdown` / `initialHtml` are now **initial-only by contract**: the seed is captured once per mount and never re-applied when prop identities change. Consumers should remount via `key` to load different initial content; re-seeding in place previously replaced live state and reset the caret.
- The demo seed-content plugin (`editor-seed-content`) tags its seed update with the same `pytah-seed` tag.

### Fixed

- The slash menu no longer steals the caret from the editor when it opens: focus landing inside the popup bounces back to the editor root (`rootElement.focus({ preventScroll: true })`).
- The table-of-contents mini-bars no longer stretch to full height on heading-heavy documents (`max-h-[70vh]` with a thin scrollbar).
